> One provider-neutral interface for whole-file cloud storage across fourteen backends, with a bring-your-own-client-id OAuth2 flow, so switching provider is a constructor change rather than a rewrite.

## 📦 Installation

```bash
dotnet add package Hawkynt.CloudStorage
```

## ✨ Features

- A single `ICloudStore` interface over fourteen providers — object stores, consumer drives and the
  classic file protocols alike.
- Whole-file semantics: download, upload, stat, delete, list, create folder. Range reads and stream
  overloads have working defaults, so a provider only overrides what it can do better.
- Bring-your-own-client-id OAuth2: loopback redirect, PKCE and refresh-token handling, so no client
  secret is baked into the library and no broker service sits in the middle.
- Provider failures are translated into a common `CloudStorageException` rather than leaking each
  SDK's own exception type.
- Official first-party SDKs only — no wrapper or meta libraries.

## 🚀 Quick start

Every store implements the same interface, so the provider is the only thing that changes:

```csharp
using Hawkynt.CloudStorage;
using Hawkynt.CloudStorage.Stores;

ICloudStore store = new S3CloudStore(bucket: "my-bucket", accessKey: key, secretKey: secret);
store.Connect();

store.Upload("reports/june.csv", File.ReadAllBytes("june.csv"));

foreach (var entry in store.List("reports"))
  Console.WriteLine($"{entry.Name} {entry.Length} bytes, modified {entry.ModifiedUtc:u}");

byte[] roundTripped = store.Download("reports/june.csv");
```

Reading a large object without buffering it whole:

```csharp
using var stream = store.OpenReadRange("backups/image.iso", offset: 0, count: 4 * 1024 * 1024);
```

## ⚠️ Limitations

- **Whole-file semantics.** There is no partial write and no in-place mutation: an upload replaces
  the object. Range support is read-only, via `OpenReadRange`.
- **Bring your own client id.** The OAuth2 providers need an application registered with that
  provider. The package ships no client id or secret, by design.
- The common interface is the intersection of what these providers agree on. Provider-specific
  features — storage classes, versioning, sharing links, quotas — are not surfaced.
- Every provider SDK is a transitive dependency, so the package pulls in a broad dependency set even
  when only one provider is used.
